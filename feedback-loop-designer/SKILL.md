# 反馈循环设计（Feedback Loop Designer）

## R — 原文

> "在练习过程中，你需要一种方法来监控你的进展……如果没有这样的反馈，你就无法知道你的练习是否有用，也不知道哪些方面需要改进。"

> — 安德斯·艾利克森，《刻意练习》第4章

---

## I — 方法论骨架

反馈是刻意练习的燃料：没有反馈，努力等于蒙眼走路。有效的反馈必须即时、具体、可行动——"不错"是无效反馈，"你第 3 句的时态错了，应该是过去时"才是有效反馈。没有导师时的替代反馈源有五类：录像回放、与标杆样本对比、数据量化、找人盲评、自我提问清单。设计原则：让反馈发生在每次练习结束时，而不是每周一次。

---

## A1 — 书中的应用

### 案例 1: 富兰克林的写作自我训练
- **问题**: 没有写作老师，如何获得反馈
- **方法论的使用**: 抄写好文章→隔日凭记忆复写→与原文逐句对比→发现差距→针对性改进
- **结果**: 用对比法制造了"标准答案"，练出高水平写作

### 案例 2: 王牌训练计划
- **问题**: 如何让飞行员在训练中快速成长
- **方法论的使用**: 模拟空战+即时评分+复盘；把反馈内嵌到每一次训练
- **结果**: 学员在训练场就把错误犯完，实战表现大幅提升

## A2 — 触发场景

### 用户会在什么情境下需要这个 skill?

1. 自学技能（写作/口语/编程）没有老师，不知道自己对不对
2. 想建立复盘系统，但只会"今天状态不错"这种模糊总结
3. 团队/个人训练想引入即时反馈机制

### 语言信号

- "怎么知道自己有没有进步"
- "没有老师/教练怎么办"
- "怎么复盘"
- "帮我设计一个反馈机制"

### 与相邻 skill 的区分

- 与 `deliberate-practice-engine` 的区别：engine 诊断反馈是否缺失，本 skill 给出搭建反馈的具体动作
- 与 `mental-representation-builder` 的关系：反馈是表征构建中"即时检索"环节的配套

## E — 可执行步骤

当 skill 被激活后，agent 应按以下步骤执行：

1. **盘点现有反馈源**
   - 问清：用户现在练习后，靠什么知道对错？（感觉？老师？考试？无）
   - 完成标准: 定位反馈缺口

2. **选择替代反馈机制**
   - 有标准答案的领域：对比法（富兰克林式）
   - 有动作过程的领域：录像回放
   - 有可量化输出的领域：数据指标
   - 有观众的领域：公开输出+他人反馈
   - 完成标准: 选 1-2 种可落地机制

3. **把反馈嵌入每次练习**
   - 设计"练习→立即检验→记录差距→下次针对性改进"的最小循环
   - 完成标准: 用户能说出下次练习结束时做什么检验
   - 判停条件: 用户想要的反馈机制成本过高（如付费教练）→ 先给零成本替代

## B — 边界

### 不要在以下情况使用此 skill

- 用户有明确导师/教练（反馈源已存在）：只需提醒 TA 主动用
- 用户处于纯情绪状态：先倾听

### 作者在书中警告的失败模式

- 无反馈的重复练习：错误模式固化，甚至能力倒退（老医生案例）

### 作者的盲点 / 时代局限

- 书中依赖"导师即时反馈"的传统模式；AI 时代的实时反馈（自动评分/智能教练）书中未涉及，可作为本 skill 的扩展场景

### 容易混淆的邻近方法论

- 复盘（PDCA）：周期更长（周/月级）；本 skill 强调单次练习结束时的即时反馈
